# webamp — task list

Guitar amp as a web app: browser page = the whole UI; tiny native helper = the
real-time audio engine (ASIO). Validated by P0 on 2026-07-18: native
WASAPI-exclusive round-trip **14.4 ms** @64 buffer vs **79.6 ms** in-browser
(full research: [`../amp-latency-research/REPORT.md`](../amp-latency-research/REPORT.md)).

Status legend: `[ ]` pending · `[~]` in progress · `[x]` done

- [x] **5. P2b: LNA permission checkpoint** — DONE 2026-07-18. Findings: (a) **Zen (user's daily browser, Firefox fork): no LNA prompt today** — `ws://127.0.0.1` from public HTTPS opens directly (Gecko loopback-WS gating is an open Mozilla bug; expect a prompt in a future release); (b) in-app Chromium 148 (Electron): LNA permissions queryable (`loopback-network` etc., "denied") but not enforced — WS opened anyway; (c) helper's Origin allowlist rejected the public origin with close 1008 in both — server-side defense carries the security regardless of browser behavior; (d) loopback mixed-content exemption confirmed (ws:// from https:// works). (e) **Consumer Chrome, observed by user Jul 18 2026: LNA permission chip appears** for `ws://127.0.0.1` from a public HTTPS origin; on deny/dismiss the handshake aborts browser-side (`ERR_CONNECTION_ABORTED`, close 1006 — never reaches the helper). Allow-path (chip → grant → open → helper origin-check) still worth one observation. P3's hosted-origin UX must explain the chip before connecting and show recovery guidance on denial (re-enable via the padlock/site-settings). Localhost page → helper → live engine state round trip verified (web/index.html).

- [x] **P3e: Tuner** — DONE 2026-07-18. Protocol checks added to ws_test (18/18).
- [x] **P3g: Audio device + channel selection / UI regroup** — DONE 2026-07-18. Engine: `enumerateDevices` (ASIO/WASAPI/WDM-KS), `AudioIO` stream-restart manager, **config persistence** (`webamp-config.json` beside the exe; device stored by name+api, resolved to index at startup). Input channel (IN 1/IN 2) live; non-ASIO device switches live; **ASIO device changes persist + apply on restart** (ASIO can't reliably re-init mid-process — verified switch-away works, switch-back defers, restart opens saved device fresh at 5.3 ms). UI: sections grouped Practice/Amp + collapsible (persisted); Cabinet moved next to Amp model; "Levels & I/O" section with input-device / input-channel / output-device pickers + meters + amber "restart to apply" note. - [x] **P3h: Rig auto-persist** — DONE 2026-07-22. The full rig now survives a helper *restart*, not just a page reload (previously only device/buffer persisted; amp params lived in engine memory and reset each launch). `Engine::ampJson()` / `Control::applyAmp()` extend `webamp-config.json` with an `amp` block: in/out gain, gate, bass/mid/treble, NAM model + cabinet IR (by display name), all 5 pedals (enabled/placement/order/params), and metronome bpm/beats/accent/vol. Writes are **debounced** (~400 ms after the last change, flushed from the meter loop + on graceful shutdown) so knob drags don't thrash the disk; device/buffer persistence is unchanged and preserved alongside. **Deliberately transient** (never persisted): `mute` (always starts muted — safety), `tunerOn`, metronome on/off. Restored at startup over the freshly-loaded defaults. Verified: WS round-trip — changed gain/tone/gate/model/IR/pedal/metro → confirmed written to config → restarted helper → every value restored, `mute` still true. Rebuilt + reinstalled (`dist/webamp-setup-0.2.0.exe`). Foundation for Presets (a named rig = this blob, keyed).
